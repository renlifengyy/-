# 模块 8：子代理（Subagents）

> 预计学习时间：1.5 小时
> 难度：中级
> 前置知识：模块 1-5

---

## 什么是子代理？

子代理是 Claude Code 中的**专业化助手**。当一个任务太复杂或需要特定专长时，主 Claude 可以把部分任务"委托"给子代理去完成。

**类比**：就像一个团队领导把代码审查交给审查专员、把测试交给测试工程师一样。

---

## 核心特点

- **独立上下文** — 每个子代理有自己独立的对话上下文，不会污染主对话
- **专业化** — 每个子代理可以有特定的指令和工具限制
- **并行执行** — 多个子代理可以同时工作
- **隔离安全** — 可以在独立的 worktree 中工作，不影响主分支

---

## 内置子代理类型

Claude Code 提供 6 种内置子代理：

| 子代理 | 用途 | 特点 |
|--------|------|------|
| `general-purpose` | 通用任务 | 拥有所有工具 |
| `Plan` | 架构设计 | 只读，专注于规划 |
| `Explore` | 代码探索 | 快速搜索和分析 |
| `code-reviewer` | 代码审查 | 专注于质量分析 |
| `test-engineer` | 测试工程 | 生成和运行测试 |
| `statusline-setup` | 状态栏配置 | 配置 UI 相关 |

---

## 子代理的工作方式

```
用户请求
    ↓
主 Claude（协调者）
    ├── 子代理 A（代码审查）  → 审查结果
    ├── 子代理 B（写测试）    → 测试代码
    └── 子代理 C（写文档）    → 文档内容
    ↓
主 Claude 汇总结果反馈给用户
```

## 自定义子代理

### 创建子代理文件

在 `.claude/agents/` 目录中创建 Markdown 文件：

```
.claude/agents/
├── code-reviewer.md
├── test-engineer.md
└── security-auditor.md
```

### 子代理文件格式

`.claude/agents/code-reviewer.md`：

```markdown
---
name: code-reviewer
description: 专业代码审查员
model: claude-sonnet-4-6
tools:
  - Read
  - Grep
  - Glob
---

你是一个专业的代码审查员。请按照以下标准审查代码：

## 审查清单

1. **正确性**：逻辑是否正确？边界条件是否处理？
2. **安全性**：是否有注入风险？敏感数据是否暴露？
3. **性能**：是否有不必要的循环或重复计算？
4. **可维护性**：命名是否清晰？结构是否合理？
5. **测试**：是否有足够的测试覆盖？

## 输出格式

对每个问题，给出：
- 文件和行号
- 问题描述
- 严重程度（高/中/低）
- 修改建议
```

### 安全审查子代理

`.claude/agents/security-auditor.md`：

```markdown
---
name: security-auditor
description: 安全审计专家
model: claude-sonnet-4-6
tools:
  - Read
  - Grep
  - Glob
---

你是一个安全审计专家。请检查代码中的安全问题：

## 检查项目

1. **注入攻击**：SQL 注入、命令注入、XSS
2. **认证授权**：密码处理、Token 管理、权限控制
3. **敏感数据**：硬编码的密钥、明文密码、日志中的敏感信息
4. **依赖安全**：已知漏洞的依赖包
5. **配置安全**：调试模式、CORS 设置、HTTP 头

## 严重程度定义

- 🔴 **Critical**：可被直接利用的漏洞
- 🟠 **High**：严重但需要特定条件才能利用
- 🟡 **Medium**：最佳实践缺失
- 🟢 **Low**：建议改进
```

### 测试工程师子代理

`.claude/agents/test-engineer.md`：

```markdown
---
name: test-engineer
description: 测试工程师
tools:
  - Read
  - Write
  - Edit
  - Bash
  - Glob
  - Grep
---

你是一个测试工程师。请为指定的代码编写全面的测试：

## 测试策略

1. **单元测试**：每个公开函数至少一个测试
2. **边界测试**：空值、极值、异常输入
3. **集成测试**：模块间的交互
4. **错误处理**：异常路径是否正确

## 测试规范

- 使用项目现有的测试框架
- 测试文件放在对应源文件的同级目录
- 测试名称要描述"什么情况下应该怎样"
- 每个测试只验证一个行为
```

## 配置选项

### YAML Frontmatter 选项

```yaml
---
name: agent-name            # 子代理名称
description: 描述            # 功能描述
model: claude-sonnet-4-6    # 模型（可选，覆盖默认）
tools:                      # 可用工具列表（限制权限）
  - Read
  - Grep
  - Glob
---
```

### 工具限制

通过 `tools` 字段控制子代理能做什么：

| 策略 | 工具列表 | 适用场景 |
|------|----------|----------|
| 只读 | Read, Grep, Glob | 代码审查、安全审计 |
| 读写 | Read, Write, Edit, Bash | 编码、测试 |
| 全能 | （不限制） | 通用任务 |

---

## 子代理 vs MCP 的选择

| 场景 | 用子代理 | 用 MCP |
|------|----------|--------|
| 需要 AI 分析和判断 | ✅ | ❌ |
| 需要调用外部 API | ❌ | ✅ |
| 需要独立的对话上下文 | ✅ | ❌ |
| 需要实时数据 | ❌ | ✅ |
| 需要并行处理 AI 任务 | ✅ | ❌ |

**简单规则**：需要"思考"用子代理，需要"连接"用 MCP。

## 实战场景

### 场景：全面的代码审查

```
你: 帮我对这个 PR 做全面审查

Claude（主）: 好的，我来安排几个专家并行审查。
  ├── 子代理 A（code-reviewer）：审查代码质量
  ├── 子代理 B（security-auditor）：检查安全问题
  └── 子代理 C（test-engineer）：评估测试覆盖

Claude（主）: 综合审查结果如下：
  1. 代码质量：发现 3 个问题...
  2. 安全性：发现 1 个高危问题...
  3. 测试覆盖：缺少 2 个关键测试...
```
