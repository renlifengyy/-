# 模块 9：高级功能（Advanced Features）

> 预计学习时间：2-3 小时
> 难度：高级
> 前置知识：模块 1-8

## 概览

本模块涵盖 Claude Code 的高级功能，这些功能可以显著提升你的开发效率和工作流的自动化程度。

| 功能 | 一句话说明 |
|------|-----------|
| 规划模式 | 先想清楚再动手 |
| 权限模式 | 控制 Claude 能做什么 |
| 扩展思考 | 让 Claude 深入思考复杂问题 |
| 后台任务 | 让任务在后台运行 |
| 自动模式 | 完全自主执行 |
| Agent Teams | 多个 Claude 协作 |
| 远程控制 | 通过 API 远程操控 |

## 1. 规划模式（Planning Mode）

### 什么是规划模式？

规划模式让 Claude 在"只读"状态下分析问题、制定计划，不会修改任何文件。适合复杂任务的前期分析。

### 使用方法

```
/plan
```

进入规划模式后：
- Claude 只能读取文件和搜索代码，不能编辑
- Claude 会制定详细的实施计划
- 你确认计划后，退出规划模式开始执行

### 适用场景

- 大规模重构前的分析
- 新功能的架构设计
- 不确定修改范围时的探索

### 示例流程

```
你: /plan
你: 我想把项目从 JavaScript 迁移到 TypeScript

Claude（规划模式）:
## 迁移计划

### 第 1 步：环境配置
- 安装 TypeScript 依赖
- 创建 tsconfig.json

### 第 2 步：核心模块迁移（按依赖顺序）
1. src/utils/ — 无外部依赖
2. src/models/ — 依赖 utils
3. src/services/ — 依赖 models
4. src/routes/ — 依赖 services

### 第 3 步：测试迁移
...

你: 计划看起来不错，开始执行吧
（退出规划模式，Claude 开始执行）
```

## 2. 权限模式（Permission Modes）

Claude Code 提供 6 种权限模式，控制 Claude 的自主程度：

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| `default` | 每次操作都需要确认 | 日常使用 |
| `acceptEdits` | 自动接受文件编辑 | 信任的修改任务 |
| `plan` | 只读模式 | 分析和规划 |
| `auto` | 完全自主执行 | 信任的自动化任务 |
| `dontAsk` | 跳过确认提示 | 熟悉的重复操作 |
| `bypassPermissions` | 绕过所有权限 | CI/CD 环境 |

### 设置方式

```bash
# 启动时指定
claude --permission-mode auto

# 在交互中切换
/config
```

### 安全建议

- 日常使用 `default` 或 `acceptEdits`
- 只在受控环境中使用 `auto` 或 `bypassPermissions`
- CI/CD 中使用 `bypassPermissions`

## 3. 扩展思考（Extended Thinking）

### 什么是扩展思考？

对于复杂问题，Claude 默认的思考可能不够深入。扩展思考让 Claude 花更多时间"想清楚"再回答。

### 使用方式

快捷键：`Alt+T`（Mac：`Option+T`）

或在对话中说：
> "请深入思考这个问题"
> "仔细分析一下这段代码的所有边界情况"

### 适用场景

- 复杂的算法设计
- 棘手的 bug 排查
- 架构决策的权衡分析
- 安全性审计

---

## 4. 后台任务（Background Tasks）

### 什么是后台任务？

让耗时的任务在后台运行，你可以继续做其他事。

### 使用方式

Claude 在处理任务时，如果检测到某些子任务可以后台执行，会自动使用。你也可以主动要求：

> "在后台运行测试套件，完成后告诉我结果"

### 典型应用

- 运行完整测试套件
- 大规模代码搜索
- 编译和构建任务
- 数据库迁移

---

## 5. 自动模式（Auto Mode）

### 什么是自动模式？

自动模式让 Claude 完全自主地完成任务，无需你逐步确认。Claude 会自动决定读什么文件、修改什么代码、运行什么命令。

### 启用方式

```bash
claude --permission-mode auto
```

### 安全机制

- 内置安全分类器，自动拦截危险操作
- 不会执行明显破坏性的命令
- 仍然尊重项目的钩子（Hooks）规则

### 适用场景

- 明确定义的任务（"修复这个 bug"、"添加这个功能"）
- CI/CD 自动化
- 批量代码修改

### 注意事项

- 首次使用时建议先用 `default` 模式走一遍流程
- 配合检查点使用，方便回退
- 不适合探索性的、需求不明确的任务

## 6. Agent Teams（团队协作）

### 什么是 Agent Teams？

多个 Claude 实例协同工作，各自负责不同的任务。

### 工作模式

```
协调者 Claude
    ├── Claude A：处理前端修改
    ├── Claude B：处理后端修改
    └── Claude C：编写测试
```

### 适用场景

- 前后端同时开发
- 大规模重构（不同模块并行修改）
- 代码审查（多角度同时审查）

---

## 7. 远程控制与 Web 会话

### Web 会话

Claude Code 不仅能在本地终端运行，还可以在浏览器中使用：
- **Web App**：通过 claude.ai/code 使用
- **Desktop App**：Mac/Windows 桌面应用

### 远程控制

通过 API 远程控制 Claude Code 实例：
- 在服务器上启动 Claude Code
- 通过 API 发送指令
- 适合自动化运维和部署

## 功能组合示例

### 示例：自动化 PR 审查流水线

```
1. 规划模式 → 分析 PR 改动范围
2. 子代理 → 并行代码审查 + 安全审计
3. MCP → 在 GitHub PR 上留评论
4. 钩子 → 自动触发测试
5. 后台任务 → 测试在后台运行
```

### 示例：大规模重构

```
1. 检查点 → 保存当前状态
2. 规划模式 → 制定重构计划
3. 自动模式 → 自动执行重构
4. Agent Teams → 多个模块并行修改
5. 检查点 → 每完成一步保存
```
