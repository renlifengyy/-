# 模块 3：检查点（Checkpoints）

> 预计学习时间：45 分钟
> 难度：入门

---

## 什么是检查点？

检查点就像游戏中的"存档"。在让 Claude 进行大量代码修改之前，你可以创建一个检查点，如果修改结果不满意，随时可以回退到之前的状态。

**本质**：检查点基于 git，它在当前状态创建一个快照，让你可以安全地实验。

---

## 核心操作

### 创建检查点

```
/checkpoint
```

或在对话中说：
> "在开始修改之前，先帮我创建一个检查点"

Claude 会自动创建一个 git 提交作为检查点。

### 查看检查点

Claude Code 会在会话中跟踪所有检查点。你可以随时问：
> "之前创建了哪些检查点？"

### 回退到检查点

```
/rewind
```

或在对话中说：
> "回退到上一个检查点"
> "撤销刚才的所有修改"

---

## 什么时候应该创建检查点？

| 场景 | 建议 |
|------|------|
| 大规模重构之前 | 必须创建 |
| 尝试新方案之前 | 强烈建议 |
| 修改关键配置文件 | 强烈建议 |
| 删除文件之前 | 建议 |
| 简单的代码修改 | 可选 |
| 只是问问题 | 不需要 |

---

## 实战场景

### 场景 1：安全重构

```
你: /checkpoint
Claude: ✓ 已创建检查点

你: 把所有的 class 组件重构成函数组件
Claude: [开始修改多个文件...]

你: 测试没通过，回退吧
你: /rewind
Claude: ✓ 已回退到检查点
```

### 场景 2：对比两种方案

```
你: /checkpoint
Claude: ✓ 已创建检查点 A

你: 用方案一实现用户认证（JWT）
Claude: [实现方案一...]

你: 我想看看另一种方案，先回退
你: /rewind

你: /checkpoint
Claude: ✓ 已创建检查点 B

你: 用方案二实现用户认证（Session）
Claude: [实现方案二...]

你: 我觉得方案一更好，回退到检查点 A 的版本吧
```

### 场景 3：增量检查点

```
你: /checkpoint    # 检查点 1：初始状态

你: 先完成数据库模型
Claude: [创建模型文件...]

你: /checkpoint    # 检查点 2：模型完成

你: 再实现 API 路由
Claude: [创建路由文件...]

你: API 路由写得不好，回退到检查点 2 重来
你: /rewind
```

---

## 工作原理

```
检查点 1 ──→ 你的修改 ──→ 检查点 2 ──→ 更多修改
    ↑                         ↑
    └─ 可以回退到这里          └─ 也可以回退到这里
```

- 检查点本质上是 git commit
- 回退（rewind）会将文件恢复到检查点时的状态
- 检查点之间的修改不会丢失（git 历史中还在）

---

## 最佳实践

1. **养成创建检查点的习惯** — 在任何有风险的操作前都创建检查点
2. **给检查点加描述** — 说"创建检查点，备注：重构前的状态"
3. **小步快跑** — 每完成一个小目标就创建检查点，而不是一次修改太多
4. **与 git 配合** — 检查点不是替代 git commit，重要的里程碑还是要正式提交

---

## 练习

1. 创建一个检查点，然后让 Claude 修改一些代码，再回退
2. 尝试创建多个增量检查点，练习在不同检查点之间切换
3. 在一个真实的重构任务中使用检查点保护你的代码
