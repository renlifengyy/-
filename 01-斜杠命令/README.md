# 模块 1：斜杠命令（Slash Commands）

> 预计学习时间：30 分钟
> 难度：入门

---

## 什么是斜杠命令？

斜杠命令是 Claude Code 中最直接的交互方式。在对话中输入 `/` 开头的命令，可以快速触发特定功能。

分为两类：
- **内置命令** — Claude Code 自带的功能
- **自定义命令** — 你自己创建的命令模板

---

## 常用内置命令一览

### 基础命令

| 命令 | 功能 | 使用场景 |
|------|------|----------|
| `/help` | 显示帮助信息 | 随时查看可用命令 |
| `/clear` | 清除当前对话 | 开始新话题时 |
| `/status` | 显示当前状态 | 查看会话信息 |
| `/config` | 打开配置 | 修改 Claude Code 设置 |

### 工作流命令

| 命令 | 功能 | 使用场景 |
|------|------|----------|
| `/plan` | 进入规划模式 | 复杂任务前先制定计划 |
| `/checkpoint` | 创建检查点 | 重要操作前保存当前状态 |
| `/resume` | 恢复会话 | 继续之前的工作 |
| `/rewind` | 回退到检查点 | 撤销不想要的更改 |

### 代码相关

| 命令 | 功能 | 使用场景 |
|------|------|----------|
| `/simplify` | 简化代码 | 审查和精简已修改的代码 |
| `/fast` | 切换快速模式 | 需要更快响应时 |

## 自定义命令

这是斜杠命令最强大的地方 — 你可以创建自己的命令模板。

### 存放位置

```
项目级（团队共享）:  .claude/commands/命令名.md
用户级（个人使用）:  ~/.claude/commands/命令名.md
```

### 创建步骤

1. 创建 `.claude/commands/` 目录
2. 在其中创建 `.md` 文件，文件名就是命令名
3. 文件内容就是发送给 Claude 的提示词

### 实战示例 1：代码优化命令

创建文件 `.claude/commands/optimize.md`：

```markdown
分析当前项目中选中的代码或最近修改的文件，从以下几个方面给出优化建议：

1. **性能优化**：找出潜在的性能瓶颈
2. **代码简化**：发现重复代码，建议抽象
3. **可读性**：改善命名、结构和注释
4. **最佳实践**：是否符合语言/框架的惯例

对每个建议，请给出：
- 问题描述
- 具体修改方案（带代码示例）
- 预期效果
```

使用：在 Claude Code 中输入 `/optimize` 即可。

### 实战示例 2：PR 准备命令

创建文件 `.claude/commands/pr.md`：

```markdown
帮我准备一个 Pull Request：

1. 查看当前分支相对于 main 的所有更改
2. 生成一个清晰的 PR 标题（英文，不超过 70 字符）
3. 编写 PR 描述，包含：
   - ## Summary（变更摘要，2-3 个要点）
   - ## Changes（详细变更列表）
   - ## Test Plan（测试计划）
4. 检查是否有遗漏的文件或未完成的 TODO
```

### 实战示例 3：带参数的命令

命令支持 `$ARGUMENTS` 占位符。创建 `.claude/commands/explain.md`：

```markdown
用简单的中文解释以下概念或代码：

$ARGUMENTS

要求：
- 先给出一句话总结
- 然后用类比解释
- 最后给一个简单的代码示例
```

使用：`/explain async/await 是什么`

---

## 小贴士

- 命令文件名不要包含空格，用 `-` 连接，如 `setup-project.md`
- 项目级命令（`.claude/commands/`）会随 git 提交共享给团队
- 用户级命令（`~/.claude/commands/`）只对你自己可见
- 可以在命令中引用其他文件：`参考 @CLAUDE.md 中的规范`

## 练习

1. 创建一个 `/review` 命令，让 Claude 审查当前文件的代码质量
2. 创建一个带参数的 `/translate` 命令，将代码注释翻译成中文
3. 尝试使用 `/plan` 命令进入规划模式，感受与普通模式的区别
